# 物品属性覆盖功能设计

## 目标

为 ItemControl 新增管理员物品属性编辑器，按已注册物品 ID 覆盖常见原版物品/方块属性。保存后的规则在重启后生效；可以删除单项或整件物品的覆盖，恢复原版行为。已修改物品在编辑列表中置顶，空闲时显示绿色边框，悬停时显示蓝色边框。

物品属性规则与玩法逻辑属于 ItemControl。KineticCore 只新增可供各附属复用的物品网格边框状态，不接收 ItemControl 的配置结构或业务规则。

## 现有基础

ItemControl 已有服务端权威配置页、权限检查、KineticCore 网络通道、物品搜索与选择，以及多处 Mixin 钩子。它尚无通用物品属性编辑器。

KineticCore 已提供 `EditedEntryTracker`、物品网格状态、主题边框、重启生效时机、物品搜索/选择、注册表访问和网络 API。它没有游戏属性覆写 API。物品数据和运行时适配器仍由 ItemControl 管理。

## ItemControl 行为

### 目标与覆盖规则

- 每条规则只指向一个精确的注册物品 ID；首版不支持标签或模组命名空间批量规则。
- 属性字段相互独立且可选。省略某字段时保留该物品当前的原版或其他模组提供的值。
- 已填写的数值是该属性的目标值，不与原值相加。攻击、护甲等属性使用物品属性修饰器的数值；玩家自身基础属性不包含在内。
- 通用属性条目包含属性注册 ID、装备槽位、运算类型和值；与同一物品/属性/槽位匹配的物品修饰器由配置值替换。
- 删除单项后重启，该项恢复原本数值；删除整条物品规则后，该物品的全部属性恢复原本行为。
- 规则适用于指定 ID 的所有物品堆，包括带不同 NBT 的堆，不提供按 NBT 区分的目标。

### 首批属性类别

1. 装备与战斗：攻击伤害、攻击速度、护甲、护甲韧性、击退抗性，以及可由通用属性条目配置的其他已注册属性。
2. 工具：挖掘速度、挖掘等级。
3. 食物：营养值、饱和度。
4. 通用物品值：最大堆叠数量、耐久上限、稀有度、防火。
5. 方块物品：其对应方块的硬度与爆炸抗性。

方块硬度和爆炸抗性修改的是对应方块定义，会影响该方块的所有状态及世界中已放置的方块，不是单个物品堆的属性。没有对应方块的物品会禁用方块属性输入。

此功能优先覆盖可用通用数值表达的原版属性。不自动重写特定物品类的独有行为，例如弓蓄力逻辑或药水专属效果；新增这类规则时需要为相应行为明确设计适配器。

### 存储与生效

- 规则存储于 `config/kineticcore/item_properties.json`，使用带版本号的 JSON 结构，以物品 ID 为键。
- 编辑/保存的待生效配置与当前进程已加载的有效配置分开。保存只更新文件和编辑器列表，不更改当前游戏进程的玩法。
- 游戏启动时从配置加载有效快照。单人游戏需完整退出并重新启动；多人游戏需重启权威服务端，客户端重连时接收该服务端的有效快照。
- 无效字段或无法解析的物品 ID 不得导致启动崩溃。保留可用项，使用 ItemControl 日志报告无效项，并向编辑界面返回本地化错误信息。
- 配置不会迁移现有物品堆的 NBT 或数量。更改堆叠上限后，存档中已有的超限堆不会自动拆分；降低耐久上限后，已有堆保留原耐久损耗值。

### 编辑器与权限

- 新建独立的 KineticCore 服务端权威配置页，避免把重启提示放到现有即时/混合生效的掉落保护设置页。
- 生效时机设为 `KTConfigPage.ApplyTiming.RESTART_GAME`，页面操作按钮打开物品属性编辑器。
- 编辑和保存要求服务端权限等级 2。服务端对每次写入重新验证权限、物品 ID、字段类型和值。
- 使用 KineticCore 物品搜索/选择、主题、滚动、控件和网络接口实现列表及属性表单。
- 使用 `EditedEntryTracker` 将有非空待生效规则的物品排在前面；通过新增的 `SUCCESS_OUTLINE` 状态显示绿色边框。悬停边框为蓝色；选择或错误状态按 KineticCore 网格状态优先级显示。
- 编辑器提供取消草稿、重置单项、重置整件物品和保存，并明确显示“重启后生效”。

## KineticCore API 扩展

向 `KineticTabs.ItemGridMarker` 以兼容方式添加 `SUCCESS_OUTLINE` 和 `WARNING_OUTLINE`。

- 现有 `SUCCESS` 与 `WARNING` 继续显示原来的角标，不改变既有调用方行为。
- 新状态在非交互状态下绘制主题色整圈边框。
- 新边框状态下的优先级为：悬停蓝色、错误红色、选中橙色、最后是状态边框颜色。这样已修改物品在鼠标悬停时仍显示蓝框。
- 通过 `GuiTheme.stateOutline` 和 `GuiTheme.indicatorOutline` 使用主题自有颜色，不要求附属硬编码颜色。
- 更新 API 文档和用法说明。KineticCore 不新增 ItemControl 的属性字段、配置结构、玩法钩子或本地化业务文案。

## 网络与错误处理

复用 ItemControl 现有 KineticCore 数据包通道和服务端权威编辑流程。客户端发送有大小限制的规则快照，不发送运行时对象。服务端解析注册 ID、校验各可选字段、原子写入待生效 JSON，再返回已接受的快照或本地化错误。单个错误项不应丢弃其他有效规则。客户端只显示服务端配置；玩法始终由服务端启动时加载的有效快照决定。

## 版本与发布

KineticCore 的网格枚举扩展保持兼容；新 API 所在版本需提升项目版本。ItemControl 使用 `SUCCESS_OUTLINE` 前，最低 KineticCore 依赖版本设为 `26.9.25`，必须大于当前的 `26.9.24`。项目启用了按日期自动版本：9 月 24 日构建仍是 `26.9.24`，发布包需在 2026-09-25 或之后构建，才满足该依赖范围。

为 CurseForge 准备简短的中英文更新说明，涵盖通用物品网格状态边框 API、ItemControl 属性编辑器、首批属性类别、重启生效与还原能力。本任务不发布或上传文件。

## 验收方案

- 分别编译 KineticCore 和引用新 API 的 ItemControl。
- 确认既有 `SUCCESS` 与 `WARNING` 角标保持不变；轮廓状态按绿/黄、悬停蓝、选中橙、错误红显示。
- 在开发世界保存护甲、工具、食物、方块的代表性覆盖值；确认当前进程数值不变，完整重启后应用新值。
- 分别重置单一属性和整件物品规则，重启后确认原版值恢复。
- 确认非法 ID/数值不会崩溃，且无权限用户不能写配置。
- 确认多人游戏客户端重连后收到服务端当前有效快照。

## CurseForge 更新说明草稿

### 简体中文

新增可复用的物品网格成功/警告边框状态，保留原有角标显示，并让悬停边框优先使用主题蓝色。ItemControl 新增按物品 ID 修改战斗属性、挖掘、食物、堆叠上限、耐久、稀有度、防火及方块硬度/爆炸抗性的编辑器。配置保存后需按提示重启；可逐项或整件恢复原值。

### English

Added reusable success and warning outline states for item grids. Existing corner badges remain unchanged, and hovered outlines keep the theme's blue color. ItemControl adds an item-ID property editor for combat attributes, mining, food, stack size, durability, rarity, fire resistance, and block hardness/explosion resistance. Saved changes require a restart and can be reset per property or per item.
