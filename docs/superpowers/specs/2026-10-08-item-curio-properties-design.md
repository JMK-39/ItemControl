# Item and accessory properties

Extend the existing ItemControl property editor while preserving its canvas, divider, category controls and save/cancel positions. Use four pixels of left-side spare room to fit nine complete item columns; retain the API's two-pixel gaps and padding. Rename its entry to Item and Accessory Properties. Curios remains optional on Forge 1.20.1, NeoForge 1.21.1 and NeoForge 26.1.2.

Saving validates and persists the document before applying a new immutable snapshot. Refresh existing equipment attributes once per save, including loaded living entities. Do not submit per keystroke or scan inventories every tick. Durability and other getter overrides immediately read the new snapshot. Default-component food/enchantability fields on 26.1.2 retain their startup behavior and clearly require a restart.

An optional `curio` object contains `enabled`, `slots`, `can_unequip`, and `attributes`. Slots accept one or multiple registered identifiers. Selecting `curio` means any Curios slot, not creating new slot types. Attribute rows use attribute/operation/amount and an add/replace/remove mode without a vanilla equipment-slot requirement. Replace/remove targets only the selected attribute, including modifiers supplied through Curios by other mods. Empty slots allow no equipment. Disabling conversion restores native Curios behavior. Configured can-unequip rules govern converted items only; administrators can unlock a rule again.

Use public Curios equip/unequip/attribute events, preserving registered ICurioItem implementations and unrelated modifiers. Load the adapter only when Curios is installed. Missing Curios greys its category and controls and displays a dependency tooltip. Slots expand inside the existing page as a bounded Kinetic toggleList().textRows() with ID plus localized name, striped rows, multiple selections and the any-slot option. Core API supplies the 2 px row gap for both selection and toggle text lists; addons do not implement their own spacing. Selection keeps the list open; Escape or an outside click closes it.

Existing accessories preselect their native slots without creating a config rule merely by browsing. Changing slot selections enables the override draft, including replacing native slots; disabling it restores native admission. A fixed-size Existing Accessories shortcut uses the existing `#curios:` tag search, without adding search logic to Core. English displays white IDs only; every other language adds gold localized names when available. Selection changes outlines only, preserving the component colors through Core's text-row renderer.

Verify existing held sword damage/durability, worn armor, modifier cleanup after reset, multi-slot and any-slot conversion, locked/unlocked removal, unrelated modifier preservation and absent-Curios loading. Use existing game profiles with sound muted and tutorial disabled. Build actual three-version JARs into D:/NEWMODS, update bilingual user documentation, push and verify exact GitHub Actions SHAs.

Missing `slots` or `can_unequip` fields inherit native Curios rules. Explicit empty slots deny all slots. Attribute-only edits must not broaden or block native admission, including Curios 15's implicit generic slot. Native-slot previews read the original rules while bypassing ItemControl overrides.
